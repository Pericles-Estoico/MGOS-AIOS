# Story 1.4: Lançamento de Custos por Etapa

## Status
Done

## Complexidade
**M** (Medium) — CRUD de lançamentos, cálculo de totais, alerta de desvio, agrupamento por etapa.

## Dependências
**Requer:** Story 1.2 (etapas de produto devem existir para receber lançamentos de custo).

## Escopo
**IN:** CRUD de lançamentos de custo por etapa, 7 tipos de custo, totais automáticos, alerta de 15%, histórico.
**OUT:** Importação de custos via CSV/planilha. Aprovação de lançamentos (workflow de aprovação). Integração com sistemas contábeis externos. Relatórios PDF.

## Riscos
- **Precisão monetária:** Ponto flutuante pode gerar erros de arredondamento. Mitigação: usar `numeric(10,2)` no banco e formatar sempre com `toFixed(2)`.
- **Alerta de 15%:** Se etapa não tiver valor planejado (zero), divisão por zero. Mitigação: tratar como "sem orçamento" — não exibir alerta.

## Executor Assignment
- executor: "@dev"
- quality_gate: "@qa"
- quality_gate_tools: ["lint", "typecheck", "vitest"]

## Story
**As a** financeiro,
**I want** lançar custos planejados e reais em cada etapa do produto,
**so that** o produto tenha um centro de custo completo com visão de orçado vs executado.

## Acceptance Criteria
1. Página `/produtos/[id]/custos` com lançamentos agrupados por etapa
2. Tipos de custo disponíveis no formulário: matéria-prima, mão de obra, terceirização, logística, embalagem, marketing, taxas-marketplace
3. Cada lançamento tem: tipo (select), descrição (text), valor planejado (number), valor real (number), data (date)
4. Totais automáticos calculados: por etapa (soma planejado, soma real) e por produto (total geral)
5. Badge de alerta vermelho visível quando `valor_real_total_etapa > valor_planejado_total_etapa * 1.15` (desvio > 15%)
6. Histórico de lançamentos por etapa com data e responsável pelo lançamento

## Dev Notes

**Tabela:** `mvp_costs` — `id, stage_id, tipo, descricao, valor_planejado, valor_real, data_lancamento, created_by, created_at`.

**RLS:** `mvp_costs` está protegido via join com `mvp_stages` e `mvp_products`. O server-side deve verificar que o `stage_id` pertence a um produto do usuário logado.

**Tipos de custo (enum):** `['materia-prima', 'mao-de-obra', 'terceirizacao', 'logistica', 'embalagem', 'marketing', 'taxas-marketplace']` — armazenar como text no banco, validar na API.

**Formatação monetária:** Usar `Intl.NumberFormat('pt-BR', { style: 'currency', currency: 'BRL' })` para exibição.

**Cálculos:** Fazer os cálculos de total e desvio no servidor (API ou Server Component) para evitar inconsistências. Não confiar em cálculos client-only.

**API Route:** `app/api/mvp/costs/route.ts` (POST) e `app/api/mvp/costs/[id]/route.ts` (DELETE, PATCH).

**Testing:**
- Testar cálculo de totais com múltiplos lançamentos
- Testar lógica de alerta de 15%
- Testar validação de campos obrigatórios
- Framework: vitest
