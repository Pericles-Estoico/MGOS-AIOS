# Story 1.7: Dashboard Geral de Produtos

## Status
Done

## Complexidade
**M** (Medium) — Dashboard com filtros, query otimizada, integração no menu existente, badges de alerta.

## Dependências
**Requer:** Story 1.5 (Gantt deve existir para o link "Ver Gantt" ser útil). Story 1.6 (Dashboard Financeiro deve existir para o link "Ver Financeiro"). Na prática, pode ser desenvolvida após 1.2 com links desabilitados temporariamente.

## Escopo
**IN:** Listagem de produtos com métricas, filtros por categoria/status/canal, ordenação, badges de alerta, acesso rápido, estado vazio, item no menu lateral.
**OUT:** Paginação (MVP assume < 100 produtos). Dashboard compartilhável com outros usuários. Exportação da lista. Gráficos de portfólio consolidado (story futura 1.9).

## Riscos
- **Regressão no menu lateral:** Editar o sidebar existente pode quebrar navegação atual. Mitigação: teste manual do dashboard de tarefas após alteração. Rollback fácil (retirar um item de menu).
- **Performance da query:** JOIN em `mvp_stages` e `mvp_costs` para métricas pode ser lento com muitos produtos. Mitigação: limitar a 100 produtos, adicionar índices na Story 1.1.

## Story
**As a** gestor,
**I want** ver todos os produtos em um painel único com alertas e filtros,
**so that** eu tenha visão completa do portfólio de produção sem precisar entrar em cada produto individualmente.

## Acceptance Criteria
1. Rota `/produtos` exibe cards ou tabela de todos os produtos do usuário logado
2. Cada produto exibe: nome, categoria, canal de venda, status geral, % etapas concluídas, custo acumulado real, data estimada de recebimento
3. Badge de alerta vermelho para produtos com etapas atrasadas; badge laranja para produtos com custo real > orçado em mais de 15%
4. Filtros funcionais: por categoria (multi-select), por status (planejado / em andamento / concluído / com atraso), por canal de venda
5. Ordenação: por data de início, por custo acumulado, por % concluído
6. Acesso rápido: botão "Ver Gantt" e botão "Ver Financeiro" em cada card/linha
7. Estado vazio com CTA "Criar Primeiro Produto" apontando para `/produtos/novo`
8. Menu lateral do dashboard existente recebe novo item "Produtos" sem quebrar outros itens

## Dev Notes

**Path do sidebar:** Localizar arquivo de menu lateral — provavelmente em `components/layout/` ou `app/(dashboard)/layout.tsx`. Adicionar item "Produtos" com ícone (usar `lucide-react` já instalado — ex: `Package` ou `Shirt`).

**Query otimizada:** Usar Supabase `select` com aggregate. Exemplo:
```typescript
const { data } = await supabase
  .from('mvp_products')
  .select(`
    *,
    mvp_stages(id, status),
    mvp_costs(valor_real)
  `)
  .eq('user_id', userId)
```
Calcular métricas em JavaScript após fetch, ou usar SQL view se performance exigir.

**Filtros via URL:** Usar `useSearchParams` do Next.js para persistir filtros na URL. Permite compartilhar URL com filtro aplicado.

**RLS:** Server Component — usar Supabase client server-side com sessão do usuário. Zero risco de expor dados de outros usuários.

**Regressão crítica:** Antes de mergear, verificar manualmente que:
- Dashboard de tarefas existente carrega normalmente
- Navegação entre páginas existentes funciona
- Menu lateral não tem sobreposição visual

**Lucide icons já instalado** (`lucide-react`). Usar `Package` ou `Shirt` ou `LayoutDashboard` para o item de menu.

**Testing:**
- Testar renderização com 0 produtos (estado vazio)
- Testar renderização com produtos em vários status
- Testar filtros e ordenação
- Testar que badges de alerta aparecem corretamente
- Framework: vitest + `@testing-library/react`
