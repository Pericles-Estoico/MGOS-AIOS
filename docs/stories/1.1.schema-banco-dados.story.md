## Acceptance Criteria
1. Tabela `mvp_products` criada: `id uuid PK`, `user_id uuid FK(auth.users)`, `nome text`, `categoria text`, `canal_venda text`, `quantidade int`, `data_inicio_plan date`, `status text DEFAULT 'planejado'`, `created_at timestamptz DEFAULT now()`
2. Tabela `mvp_stages` criada: `id uuid PK`, `product_id uuid FK(mvp_products)`, `nome text`, `ordem int`, `data_inicio_plan date`, `data_fim_plan date`, `data_inicio_real date`, `data_fim_real date`, `status text DEFAULT 'planejada'`, `responsavel_id uuid FK(auth.users)`
3. Tabela `mvp_costs` criada: `id uuid PK`, `stage_id uuid FK(mvp_stages)`, `tipo text`, `descricao text`, `valor_planejado numeric(10,2)`, `valor_real numeric(10,2)`, `data_lancamento date`, `created_by uuid FK(auth.users)`, `created_at timestamptz DEFAULT now()`
4. Tabela `mvp_category_templates` criada: `id uuid PK`, `categoria text UNIQUE`, `stages jsonb NOT NULL`, `created_at timestamptz DEFAULT now()`
5. RLS habilitado em todas as tabelas `mvp_*`. Policy em `mvp_products`: usuário acessa apenas `user_id = auth.uid()`. Policies em `mvp_stages` e `mvp_costs` via join com `mvp_products`
6. Seed com templates padrão para 7 categorias: camiseta, calça, vestido, conjunto, moda-infantil, jaqueta, acessorio — cada uma com etapas padrão em JSONB
7. Migration executada sem erros; `supabase db diff` confirma que tabelas existentes não foram alteradas

## Dev Notes

**Stack de banco:** PostgreSQL via Supabase. Migrações em `supabase/migrations/`. Aplicar com `supabase db push`.

**Prefixo obrigatório:** Todas as tabelas novas usam prefixo `mvp_` para isolamento do schema existente (que tem: `users`, `tasks`, `evidence`, `qa_reviews`, `audit_logs`, `time_logs`, `notification_preferences` e outras).

**Padrão de RLS do projeto existente:** Auth via `auth.uid()` do Supabase. Ver tabelas existentes para padrão de policy.

**Estrutura JSONB para templates:**
```json
{
  "stages": [
    { "nome": "Inventário de Insumos", "ordem": 1, "duracao_dias": 2 },
    { "nome": "Planejamento da Sprint (PCP)", "ordem": 2, "duracao_dias": 1 },
    { "nome": "Compra/Reposição", "ordem": 3, "duracao_dias": 3 }
  ]
}
```

**Etapas padrão por categoria (base no fluxo de confecção):**
- Planejamento & Insumos: Inventário, PCP, Compra
- Corte & Preparação: Enfestamento, Corte, Separação/Loteamento
- Costura: etapas específicas por peça (Fechar Ombro, Mangas, etc.)
- Acabamento: QA, Passadoria, Etiquetagem
- Vendas: Cadastro Ecommerce, Marketing, Expedição, Recebimento

**Testing:**
- Testes em `supabase/tests/` ou `__tests__/db/`
- Verificar policies via `supabase test db`
- Framework: vitest (já configurado no projeto, `vitest.config.ts`)
