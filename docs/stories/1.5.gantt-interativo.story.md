# Story 1.5: Gantt Interativo

## Status
Done

## Complexidade
**H** (High) — Componente visual complexo com lógica de grid de tempo, múltiplos estados visuais, requisito de performance (< 2s com 50 etapas).

## Dependências
**Requer:** Story 1.3 (etapas com datas reais e status para renderizar barras corretas). Story 1.4 (custos por etapa para tooltip).

## Escopo
**IN:** Gantt com barras por status, linha "hoje", tooltip, zoom semana/mês, scroll mobile.
**OUT:** Edição de datas via drag-and-drop no Gantt. Exportar Gantt como imagem/PDF. Comparativo entre múltiplos produtos no mesmo Gantt.

## Riscos
- **⚠️ RISCO CRÍTICO — Biblioteca de Gantt:** Decisão de implementação (customizada vs biblioteca) deve ser tomada pelo @architect ANTES de começar. Uma biblioteca errada pode adicionar 200KB+ ao bundle. Mitigação: @architect valida antes do @dev começar esta story.
- **Performance com 50 etapas:** Grid de datas calculada para muitas etapas pode ser lenta. Mitigação: `useMemo` para cálculos, virtualização se necessário.
- **Scroll mobile:** Layout pode quebrar em telas pequenas. Mitigação: testar em 375px durante desenvolvimento.

## Story
**As a** gestor,
**I want** visualizar o ciclo do produto em um Gantt interativo,
**so that** eu enxergue a linha do tempo completa com planejado vs real e identifique atrasos de forma visual.

## Acceptance Criteria
1. Gantt disponível na página `/produtos/[id]` como seção principal (tab ou seção expandida)
2. Cada linha do Gantt representa uma etapa. Colunas representam dias/semanas na linha do tempo
3. Barras coloridas por status: cinza (planejada), azul (em andamento), verde (concluída), vermelho (atrasada). Barra dupla mostrando planejado vs real quando datas reais existem
4. Linha vermelha vertical marcando a data de hoje
5. Tooltip ao hover em cada barra: nome da etapa, data início plan/real, data fim plan/real, custo acumulado da etapa, responsável, status
6. Zoom/navegação: botões para alternar entre visão semanal e mensal
7. Renderiza com até 50 etapas em menos de 2 segundos
8. Scroll horizontal funcional em telas mobile (≥ 375px)

## Dev Notes

**Decisão de biblioteca:** @architect deve aprovar antes de adicionar nova dependência de Gantt. Se implementação customizada, usar apenas Tailwind + CSS grid/flexbox. Se biblioteca, preferir `gantt-task-react` (leve) ou implementar com SVG.

**Dados necessários:** `mvp_stages` (todas as etapas com datas plan/real/status) + `mvp_costs` (para custo acumulado por etapa no tooltip).

**Cálculo de grid:**
- Semanas: colunas de 7 dias
- Meses: colunas por mês
- Span de datas: `min(data_inicio_plan)` até `max(data_fim_plan, data_fim_real, today + 7 dias)`

**Cores de status (Tailwind):**
- planejada: `bg-gray-300`
- em_andamento: `bg-blue-500`
- concluida: `bg-green-500`
- atrasada: `bg-red-500`

**Mobile:** Colocar o Gantt em container `<div className="overflow-x-auto">`. Largura mínima da grade = número de semanas × 80px.

**Recharts já instalado** — pode usar para gráficos no tooltip se necessário, mas o Gantt em si deve ser componente customizado.

**Testing:**
- Testar renderização com dados mock (etapas passadas, futuras, sem datas reais)
- Testar posicionamento da linha "hoje"
- Testar cálculo de colunas para zoom semana/mês
- Framework: vitest + `@testing-library/react`
